# v1.9.5：使用自有 GitHub OAuth 应用

源码版本更新为 **1.9.5+47**。GitHub 登录不再默认使用第三方注册的 OAuth 应用，改为由构建者显式配置自己的公开 Client ID。

## OAuth 应用身份与构建配置

- 删除内置第三方 Client ID 的回退值。GitHub 授权页的应用名称和所属账号由构建时选择的 OAuth App 决定，与 APK 显示名称、包名及正在登录的 GitHub 账号不是同一概念。
- 本地构建通过 `--dart-define="GITHUB_OAUTH_CLIENT_ID=<your-client-id>"` 注入自有 Client ID；该 OAuth App 需要启用 Device Flow。此配置不需要 Client Secret，也不需要提供用户 Token。
- Android 和 iOS CI 统一读取仓库 Actions variable `GITHUB_OAUTH_CLIENT_ID`，不再在工作流中硬编码第三方 ID。修改变量后，需要重新构建安装包才会生效。
- 未配置或只填写空白时，CI 明确警告但继续构建；安装包尝试 GitHub Device Flow 登录时会提示缺少配置，不会悄悄使用其他人的应用。**手动 Token、WebDAV 和 S3 仍可使用。**

申请的权限**保持 `gist read:user` 不变**，本次修改没有自动扩大或缩小授权范围。Device Flow 请求仍直接发往 GitHub 官方端点；请在授权页核对自有应用的所属账号和权限后再确认。

生成可用的自有 OAuth 登录 APK 前，必须先完成上述公开 Client ID 配置。详细设置及令牌过期选项见 [开发说明](https://github.com/pandablin/Netcatty-mobile/blob/v1.9.5/docs/DEVELOPMENT.md#初始化)。

## 升级与已有授权

更换 Client ID 不会把已保存的旧应用 Token 自动换成新应用 Token，也不会自动撤销旧授权。如先前使用旧应用登录，需要退出后通过配置了自有 Client ID 的版本重新授权；旧应用授权可在 GitHub 的授权管理中自行检查和撤销。

本次本地测试包继续显示 **Netcatty**，使用独立包名 `app.netcatty.mobile.audit`，并沿用上一版本地测试签名；它与 wxte 原版的安装身份不同。源码通用配置仍保留 `app.netcatty.mobile`，CI 产物的身份和签名以对应构建清单为准。

## 验证边界

认证回归使用虚构 Client ID 和内存 HTTP 客户端，覆盖自有 ID 注入、缺配置时停止授权请求，以及已有 Token 查询不依赖 Client ID；新增错误提示同时提供英文渲染。

本说明不声称已使用最终自有 OAuth App 完成在线登录，也不声称 GitHub Actions 已运行。最终安装包、签名和摘要应以实际构建后随附的校验记录为准。
